# ProFolio Terminal

## Institutional Quant ML Analytics for Indian Stock Portfolios

**ProFolio Terminal** is a full-stack quantitative portfolio analytics
application that combines broker portfolio synchronization, historical
market data, machine-learning-based **T+1 price prediction**, portfolio
NAV projection, model evaluation, and interactive financial charts.

The application currently supports **Upstox OAuth portfolio
synchronization** and **manual portfolio analysis**.

> **Important:** ProFolio Terminal is an academic/technical project. Its
> predictions are generated by quantitative models and are intended for
> analytical and educational purposes only. They are **not financial
> advice** and should not be treated as a recommendation to buy, sell,
> or hold any security.

# Overview

ProFolio Terminal is designed to provide an end-to-end interface for
analyzing Indian equity portfolios using historical market data and
machine-learning regression models.

The system can:

1.  Accept a portfolio manually or synchronize holdings from Upstox.
2.  Normalize Indian stock symbols into Yahoo Finance-compatible
    symbols.
3.  Retrieve historical daily market data.
4.  Generate time-series features from historical closing prices.
5.  Train a selected regression model.
6.  Predict the next business day's closing price (**T+1**).
7.  Calculate expected price movement.
8.  Project portfolio-level NAV.
9.  Calculate portfolio alpha/expected change.
10. Report an R²-based model evaluation score.
11. Display historical prices and predictions through interactive
    charts.
12. Support line, area, candlestick, and bar visualizations.
13. Provide what-if scenario simulation.
14. Allow the user to select the ML model and historical lookback
    period.

# Machine Learning Models

## 1. Linear Regression

Linear Regression is the baseline regression model.

It learns the relationship between historical price-derived features and
the next closing price.

### Features

``` text
lag_1
lag_2
SMA_5
SMA_10
```

### Output

``` text
Predicted T+1 Closing Price
```

### Purpose

-   Simple baseline
-   Fast training
-   Easy interpretation
-   Comparison with more complex models

------------------------------------------------------------------------

## 2. XGBoost Regressor

XGBoost is a gradient-boosting regression algorithm based on decision
trees.

Current configuration:

``` text
n_estimators = 35
max_depth = 3
learning_rate = 0.08
random_state = 42
```

### Purpose

XGBoost can capture nonlinear relationships that a simple linear model
may not capture.

------------------------------------------------------------------------

## 3. LightGBM Regressor

LightGBM is another gradient-boosting framework for tree-based learning.

Current configuration:

``` text
n_estimators = 100
learning_rate = 0.05
max_depth = 3
num_leaves = 15
min_child_samples = 10
subsample = 0.8
colsample_bytree = 0.8
random_state = 42
```

### Purpose

LightGBM provides another gradient-boosting approach for model
comparison.

------------------------------------------------------------------------

## 4. Exponential Trend Proxy

The Trend Proxy combines:

-   Linear Regression prediction
-   Exponential Moving Average

Current calculation:

``` text
Trend Prediction =
0.6 × Linear Regression Prediction
+
0.4 × EMA Prediction
```

The EMA uses a span of 5.

### Purpose

It combines a regression prediction with a recent-price trend component.

# Feature Engineering

The ML engine creates four primary features from historical closing
prices.

## Lag 1

``` text
lag_1 = Close(t-1)
```

Previous trading day's closing price.

## Lag 2

``` text
lag_2 = Close(t-2)
```

Closing price from two trading days earlier.

## SMA 5

``` text
SMA_5 = mean(previous 5 closes)
```

## SMA 10

``` text
SMA_10 = mean(previous 10 closes)
```

The rolling averages are shifted so future information is not included
in the training features, helping reduce data leakage.

------------------------------------------------------------------------

# T+1 Prediction

The project predicts the **next business day's closing price**.

The prediction date is generated using a business-day offset rather than
simply adding 24 hours.

``` text
Latest Trading Day
        ↓
Next Business Day
        ↓
T+1 Prediction
```

If there is insufficient historical data, the engine falls back to the
latest available price instead of attempting to train an unreliable
model.

# Portfolio Analytics

For each holding:

## Current Position Value

``` text
Current Value =
Current Price × Quantity
```

## Projected Position Value

``` text
Projected Value =
T+1 Predicted Price × Quantity
```

## Expected Price Change

``` text
Expected Change % =
((Predicted Price - Current Price)
 / Current Price) × 100
```

## Portfolio NAV

``` text
Current NAV =
Σ(Current Price × Quantity)
```

``` text
Projected NAV =
Σ(Predicted Price × Quantity)
```

## Portfolio Alpha / Expected Change

``` text
Portfolio Alpha % =
((Projected NAV - Current NAV)
 / Current NAV) × 100
```

The frontend presents these results at both stock and portfolio levels.



``` text

trend
```


``` json
    },
    {
      "symbol": "TCS.NS",
      "quantity": 5
    }
```

# Model Evaluation

The project calculates an **R² score** for the selected regression
model.

The feature dataset is split chronologically:

``` text
80% → Training
20% → Testing
```

The test-set R² is used when enough test samples are available.
Otherwise, the training score is used as a fallback.

The returned R² is an evaluation metric, not a guaranteed probability
that a prediction will be correct.

# Security and Privacy

The current backend is designed around a stateless analysis flow.

The Upstox access token is received during the request, used to retrieve
holdings, and is not intentionally stored in a persistent application
database by the current implementation.

Best practices:

-   Never commit `.env`.
-   Never expose `UPSTOX_CLIENT_SECRET` in frontend code.
-   Use HTTPS in production.
-   Store secrets using deployment-platform environment variables.
-   Restrict CORS to trusted origins.
-   Never publish real OAuth tokens in screenshots, issues,
    documentation, or source code.
